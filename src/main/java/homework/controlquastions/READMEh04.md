Відповіді на відкриту дискусію Підготуйте ці відповіді для усного опитування або захисту практики:

Навіщо в програмуванні окремий тип для «так» і «ні»?

Для чіткої логічної типізації коду, запобігання помилкам (щоб випадково не порівняти число з прапорцем) та оптимізації пам’яті.

Як сказати !(a && b) людською мовою?

За законом Де Моргана: «Неправда, що виконані обидві умови одночасно» (або «Хоча б одна з умов не виконується», тобто !a || !b).

Чим && відрізняється від &?

&& — це логічне «І» з коротким замиканням (short-circuit evaluation): якщо лівий вираз false, правий вираз навіть не обчислюється.

& — перевіряє обидві частини завжди, незалежно від результату першої (а також виконує побітове «І» для чисел).

Чому програма не падає в if (x != null && x.name == "Іван"), хоча x порожній?

Завдяки короткому замиканню &&. Оскільки x != null повертає false, перевірка x.name == "Іван" взагалі не виконується, тому NullPointerException не виникає.

Як запхати 32 відповіді «так/ні» в одне число?

Використати бітову маску (bitmask). Число типу int займає 32 біти, де кожен біт — це окремий прапорець (1 = так, 0 = ні). Перевірка і зміна значень робиться за допомогою побітових операцій (&, |, ^, <<, >>).

Що швидше: n % 2 чи n & 1?

n & 1 швидше, тому що це одна пряма побітова інструкція процесора. Операція ділення з остачею % арифметично складніша для обчислення.
